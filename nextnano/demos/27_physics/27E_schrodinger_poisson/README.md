## Pass condition

Both arms converge (a quantum_poisson run that exits DONE without converging is a FAIL, not a result - the evidence is the convergence warning in summary.log and the residuals in iteration_quantum_poisson.dat, both of which are checked), and the Hartree potential, charge density, band edges, state energies, localization and matrix elements are compared arm to arm. PASS means the size of the electrostatic effect is quantified, whatever that size is.

## The controlled change

Whether Poisson is solved self-consistently with the Schroedinger equation. Both decks are otherwise the Demo 23 baseline structure, so the pair isolates electrostatics. Note that the flat-band arm is regenerated rather than reused from Demo 23: if 27D changes the geometry decision, both arms must move together, and a control from a different structure would not be a control.

Fields this sub-demo may change: `electrostatics`.
At most **1** per deck. Everything else is inherited verbatim from the Demo 23 baseline, and `framework/registry.resolve` raises rather than generating a deck that breaks either rule.

## Cost

**Basis:** The flat-band arm costs one Demo 23 production run (10 min 20 s measured). The self-consistent arm repeats the quantum solve once per Poisson iteration, so it is the iteration count times that, and Demo 6 needed tens of iterations on a much smaller problem. 2-8 h is the honest range; the run is capped by --timeout and by the iteration limit in the deck.

`outputs/COST_STATEMENT.md` is regenerated by preflight from the resolved configuration, so it reflects the decks that actually exist rather than this document.

## Why the control is regenerated rather than reused

Demo 23's production run is a valid flat-band control for six other sub-demos.
It is deliberately **not** used here. If 27D changes the geometry decision, both
arms of 27E must move together; a control taken from a different structure is not
a control. The two decks in this directory are therefore generated as a matched
pair, and the cost statement counts both.

## Doping: unresolved, and not invented

The paper's carrier input is not known. Demo 26 records this as hypothesis 4 with
the note *"unknown carrier inputs in paper"*. Demo 27 will not invent doping to
manufacture a difference, so both arms are undoped and what they measure is the
solver's own self-consistent redistribution of the states' charge.

`config.yaml` records this as `carrier_input_decision: UNRESOLVED_NO_DOPING_ASSUMED`.
If a carrier density is ever established, add it as a `doping:` entry **with its
justification** — `framework/decks.Doping` refuses a region whose `justification`
string is empty, so an undocumented carrier density cannot reach a deck.

## Convergence is a pass condition, not a detail

`run{ quantum_poisson{} }` exits DONE and writes `job_done.txt` **even when it has
not converged**. Demo 6 measured this on nextnano++ 3.0.0. The only in-file
evidence is `WARNING: QUANTUM-POISSON failed to converge.` in `summary.log` plus
the final residuals in `iteration_quantum_poisson.dat`. Both are checked, and a
non-converged run is a FAIL rather than a result.

Do not raise `residual` or lower `iterations` to make a run "pass".

## Contact placement

A contact attached to `everywhere{}` makes the whole domain a Dirichlet region,
so once Poisson runs the potential is pinned everywhere and no band bending can
appear — Demo 6 measured a potential flat to 1e-10 kV/cm despite an imposed
100 kV/cm. The generated decks attach the contact to a line region over the
domain, inherited from the Demo 22/23 template that these runs must stay
comparable to. If arm B shows exactly zero bending, check this first.

## Data harvest

Whenever this sub-demo's decks are solved, the shared broad harvest in `demo27_config.yaml` is requested — eigenenergies, envelopes, kp8 spinors, CB/HH/LH/SO character, probabilities, transition energies, dipole and momentum matrix elements, oscillator strengths, band edges, alloy composition, k vectors, dispersions and masses, plus electrostatic potential and strain where the deck already computes them.

No expensive new physics is enabled merely because an output would be interesting. The harvest costs disk, not solver time.
