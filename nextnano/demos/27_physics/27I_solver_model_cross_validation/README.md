## Pass condition

The same physical structure is solved with three models and the state energies, transition energies and optical matrix elements are tabulated side by side. PASS means each of the six Equation 2 features is attributed to the simplest model that reproduces it. The comparison must be like-for-like: the geometry, mesh, temperature and domain are identical across arms, which is exactly what the single controlled change guarantees.

## The controlled change

The quantum model. The single-band deck also drops the k path, because a decoupled Gamma/HH model has no in-plane k dependence to sample in this deck form - that is the second field, and it is a consequence of the first rather than an independent choice.

Fields this sub-demo may change: `band_model`, `k_mode`.
At most **2** per deck. Everything else is inherited verbatim from the Demo 23 baseline, and `framework/registry.resolve` raises rather than generating a deck that breaks either rule.

| Deck | Changed fields | Question |
|---|---|---|
| `model_kp6_valence` | `band_model` | Which features survive a 6-band valence treatment with a decoupled conduction band? |
| `model_single_band` | `band_model`, `k_mode` | Which features survive a decoupled parabolic Gamma/HH treatment? |

## Tier note

Planned as Tier 2-3. The single-band arm has no k dependence to compute and finishes in seconds; the kp6 arm solves 6 bands instead of 8 over the same path. Against the reused kp8 arm from Demo 23 this is well inside Tier 1.

## Cost

**Basis:** The single-band arm is an ordinary 1D Schroedinger solve on 600 grid points and takes seconds. The kp6 arm is the Demo 23 production cost scaled by roughly (6/8), i.e. minutes. The kp8 arm is not rerun: it is demo_results/demo23/raw/production_y_n301_k0100 on this exact structure.

`outputs/COST_STATEMENT.md` is regenerated by preflight from the resolved configuration, so it reflects the decks that actually exist rather than this document.

## The question

Which spectral features are *consequences of the 8-band k.p treatment* and which
survive a simpler model? If a feature appears in a decoupled parabolic model, the
multiband physics is not what produces it, and looking for the disagreement in
band mixing is looking in the wrong place.

## The arms

| Model | Deck | Blocks |
|---|---|---|
| kp8 | **reused** — `demo_results/demo23/raw/production_y_n301_k0100` | `kp_8band{}` |
| kp6 valence + decoupled Gamma | `model_kp6_valence` | `Gamma{ num_ev }` + `kp_6band{ num_ev }` |
| single band | `model_single_band` | `Gamma{ num_ev }` + `HH{ num_ev }` |

The single-band deck also drops the k path, because a decoupled Gamma/HH model
has no in-plane k dependence to sample in this deck form. That is the second
changed field, and it is a consequence of the first rather than an independent
choice — `max_fields_per_deck: 2` in the config.

## Grammar note, measured not assumed

The optical output blocks need a model tag, and the two block families accept
**different** tag sets. Read out of `nextnano++/keywords/keywords_nnp.xml` and
confirmed with `--parse` against nextnano++ 3.0.0:

- `dipole_moment_matrix_elements` and `momentum_matrix_elements` accept only
  single-model tags: `Gamma X Delta L HH LH SO KP6 KP8 KP14 KP30`.
- `transition_energies` accepts those **and** the cross-band pair tags
  (`Gamma_HH`, `Gamma_KP6`, `HH_LH`, ...).

So the single-band deck writes `transition_energies{ Gamma_HH{} }` but
`dipole_moment_matrix_elements{ ... Gamma{} HH{} }`. `framework/decks.py` holds
both tables. The first attempt used one table for both and nextnano++ rejected
it — which is why preflight runs `--parse` over every deck rather than trusting
the generator.

## Like-for-like, or nothing

The comparison is only meaningful if geometry, mesh, temperature and domain are
identical across arms. That is exactly what the single controlled change
guarantees, and `outputs/CONTROLLED_CHANGE_DIFF.md` shows it line by line.

## Why it is cheap

The single-band arm is an ordinary 1D Schroedinger solve on ~600 grid points and
takes seconds. The kp6 arm is the Demo 23 production cost scaled by roughly 6/8.
Against a reused kp8 arm this is Tier 1, not the Tier 2-3 originally planned.

## Data harvest

Whenever this sub-demo's decks are solved, the shared broad harvest in `demo27_config.yaml` is requested — eigenenergies, envelopes, kp8 spinors, CB/HH/LH/SO character, probabilities, transition energies, dipole and momentum matrix elements, oscillator strengths, band edges, alloy composition, k vectors, dispersions and masses, plus electrostatic potential and strain where the deck already computes them.

No expensive new physics is enabled merely because an output would be interesting. The harvest costs disk, not solver time.
