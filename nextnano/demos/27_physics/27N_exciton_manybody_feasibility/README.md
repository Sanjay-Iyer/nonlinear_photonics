`--preflight` needs no license and runs anywhere. `--physics` refuses to start against a Free build, refuses without `--yes`, and refuses while a prerequisite is unmet. `--analyze` never launches a solver.

## Pass condition

Three numbers are produced with their assumptions stated: an estimated 2D exciton binding energy for this well pair, an estimated Coulomb enhancement of the interband resonances, and an estimated screening / state-filling correction at the experiment's carrier density. Each is compared against the measured paper-vs-model feature gaps in Demo 26's EXTENDED_FEATURE_DIAGNOSIS.csv. PASS is the recommendation - IMPLEMENT or DO NOT IMPLEMENT - with the arithmetic shown. Building a many-body solver is explicitly NOT in scope here.

## The controlled change

None. 27N runs no solver and generates no deck.

This sub-demo changes no deck field.

## Tier note

Planned as Tier 4-5. The FIRST pass is deliberately a feasibility study, not an implementation: estimate the binding energy, the Coulomb enhancement and the screening from the structure Demo 27 already has, and compare those numbers against the size of the disagreement. That costs no solver time. A many-body solver is only justified if the estimate says the effect is comparable to the gap being explained, and this sub-demo's job is to answer that question before anyone builds one.

## A feasibility study, not an implementation

The first pass produces three numbers with their assumptions stated, and one
recommendation. It runs no solver and builds no many-body code.

| Estimate | Compared against |
|---|---|
| 2D exciton binding energy for this well pair | the paper-vs-model feature gaps |
| Coulomb enhancement of the interband resonances | the amplitude discrepancy |
| screening / state-filling correction at the experiment's carrier density | both |

The comparison target is Demo 26's `EXTENDED_FEATURE_DIAGNOSIS.csv`: P1 is
148 nm off, Z1 115 nm, Z2 125 nm. If the estimated excitonic shift is an order of
magnitude smaller than that, the answer is DO NOT IMPLEMENT, and it is worth far
more than a half-built many-body solver.

## nextnano may already do the first estimate

`transition_energies{}` has a native `excitons{ electron_mass hole_mass
density_averaged_masses dielectric_const }` sub-block in the 2026_07_03 grammar.
Try that route before writing anything: it needs no new tooling and it attaches
the estimate to the same states the rest of the campaign uses.

## Scope discipline

Do **not** implement a large many-body solver unless the arithmetic above says
the effect is comparable to the gap being explained. The recommendation, with the
arithmetic shown, is this sub-demo's deliverable. Building the solver would be a
new sub-demo with its own tier and its own cost statement.

## Data harvest

Whenever this sub-demo's decks are solved, the shared broad harvest in `demo27_config.yaml` is requested — eigenenergies, envelopes, kp8 spinors, CB/HH/LH/SO character, probabilities, transition energies, dipole and momentum matrix elements, oscillator strengths, band edges, alloy composition, k vectors, dispersions and masses, plus electrostatic potential and strain where the deck already computes them.

No expensive new physics is enabled merely because an output would be interesting. The harvest costs disk, not solver time.
