```bash
python nextnano/demos/27_physics/run_demo27.py --demo 27M --preflight
```

```bash
python nextnano/demos/27_physics/run_demo27.py --demo 27M --analyze
```

```bash
python nextnano/demos/27_physics/run_demo27.py --demo 27M --record PASS --conclusion "..."
```

`--preflight` needs no license and runs anywhere. `--physics` refuses to start against a Free build, refuses without `--yes`, and refuses while a prerequisite is unmet. `--analyze` never launches a solver.

## Pass condition

The Equation 2 pathways are decomposed by spin branch and by band character using 27B's harvested spinors, and the decomposition either accounts for a named spectral discrepancy or does not. PASS is reached when the decomposition exists and its conclusion is stated. If a decisive quantity turns out to be missing from the harvest, that is also a PASS, provided the missing quantity is named and a costed deck is proposed.

## The controlled change

None. 27M changes no deck and runs no solver. It reads 27B's harvest, which is why the harvest was requested broadly in the first place.

This sub-demo changes no deck field.

## Tier note

Planned as Tier 4 on the assumption that new decks would be needed. They are not, for the first pass: 27B's harvest already contains the full kp8 spinors, the CB/HH/LH/SO fractions and the polarization-resolved matrix elements at every k, which is what a spin- and branch-resolved decomposition needs. This is the campaign's collect-broadly rule paying for itself. If the decomposition then shows a quantity that was NOT harvested is decisive, that finding is recorded and a Tier 4 deck is proposed at that point - not before.

## Cost

**Basis:** Post-processing of 27B's output. The cost is parsing time over the finite-k envelope and spinor files, which Demo 25 estimates at 2-10 minutes for a 301-point production run.

`outputs/COST_STATEMENT.md` is regenerated by preflight from the resolved configuration, so it reflects the decks that actually exist rather than this document.

## No decks. No solver. This is the harvest paying for itself.

27M was planned as a Tier 4 sub-demo needing its own Professional runs. It does
not need them, because 27B's harvest already contains what a spin- and
branch-resolved decomposition requires: the full kp8 spinors, the CB/HH/LH/SO
fractions and the polarization-resolved matrix elements, at every k.

That is the entire point of the campaign's collect-broadly rule. The marginal
cost of requesting those outputs during 27B is disk; the cost of *not* requesting
them would have been a second multi-hour Professional run here.

## What it decomposes

- spin-resolved contributions to each Equation 2 pathway
- branch-resolved response (which valence branch carries which feature)
- strong HH/LH/SO mixing regions in k, and what they do to the pathway numerators
- complex multicomponent matrix elements, kept complex rather than reduced early
- Kramers-pair consistency as a check on the spinor bookkeeping

## The honest failure mode

If the decomposition shows that a quantity which was **not** harvested is
decisive, that is also a pass — provided the missing quantity is named and a
costed deck is proposed at that point. What is not acceptable is quietly
enabling new expensive physics because an output looked interesting. The harvest
rule cuts both ways.

## Data harvest

Whenever this sub-demo's decks are solved, the shared broad harvest in `demo27_config.yaml` is requested — eigenenergies, envelopes, kp8 spinors, CB/HH/LH/SO character, probabilities, transition energies, dipole and momentum matrix elements, oscillator strengths, band edges, alloy composition, k vectors, dispersions and masses, plus electrostatic potential and strain where the deck already computes them.

No expensive new physics is enabled merely because an output would be interesting. The harvest costs disk, not solver time.
