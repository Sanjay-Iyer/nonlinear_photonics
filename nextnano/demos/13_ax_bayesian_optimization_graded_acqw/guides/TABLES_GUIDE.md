# Demo 13 tables guide

_Generated by `guides13.py` — edit that, not this file._

Every table is a **projection of the immutable trial ledger**, rebuilt from it on each run, so regenerating a table can never put history at risk. Each CSV has a `.units.json` sidecar naming the unit of every column.

**Current result (experiment v3).** 23 proposals, 7 refused before the solver ran, 16 completed with no solver failures, **3 feasible**. The best feasible trial is **t0021** (asymmetry 0.387565, central barrier 0.85 nm, abrupt, relative chi2 at 1550 nm = 0.411027, detuning -13 nm). t0021 sits on the barrier **lower bound** and Stage 5 has not run, so it is the best design *found*, **not a validated optimum**.

**Units.** Every chi(2) number in this demo is a *relative* merit in arbitrary units (`a.u. (relative |chi2|)`). It is a lineshape and a trend with no absolute calibration. It is **never pm/V**, and values are only comparable between designs computed with the same mesh and settings.

**No table silently drops a trial.** Invalid and refused proposals have their own tables *and* stay in the complete history with their reason.

## The four tables that answer 'what happened?'

| Table | Question it answers |
|---|---|
| `bo_budget_accounting` | How many proposals, refusals, evaluations? |
| `bo_candidate_rejection_history` | Why was each refused proposal refused? |
| `bo_trial_iteration_mapping` | Which trial was which BO iteration? |
| `bo_proposed_vs_realized_grading` | What was asked for vs what was built? |

### Common mistakes

- Reading the ledger's `iteration` column as the BO iteration. It counts **proposal attempts** and reached 17 in a 10-iteration study. Use `mbm_iteration_number` from `bo_trial_iteration_mapping`.
- Treating a refused proposal as a failed trial. Nothing was simulated; its `realized_interface_mode` is `not_realized`, not `abrupt`.
- Comparing objectives across feasible and infeasible trials. Only the 3 feasible v3 trials are comparable as candidate designs.
- Reading `parameter_grading_thickness_nm` on a *refused* row. That column holds the canonicalized design and shows 0 nm; use the proposed columns.
